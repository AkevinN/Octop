# 设计文档：行内系统对接

> spec：`p2-06-intranet-integration` ｜ 波次：二期 ｜ 基线：`757fd12` ｜ 预估：34–40 人日
> 前置：`w0-01-fork-migration-namespace`、`w0-02-ci-gates`、`w0-04-fork-isolation-points`、`w0-05-ssrf-intranet-allowlist`、`w1-01-security-hotfix`、`w2-01-offline-build`、`w2-04-intranet-model-gateway`、`w3-03-authorization-foundation`、`w3-05-credential-encryption` ｜ 全局约束：`.kiro/steering/intranet-transformation.md`

## 概述

本 spec 交付五组彼此独立、可分别合入的能力：供应商级 TLS/代理、行内 IM 通道、行内三类连接器、多维配额、银行专家模板。前提是 Wave 0–4 已全部合入，一期落地后代码会有较大变化，多数具体锚点（尤其 IM 通道与连接器的行号）标注为"实施时以路径 + 符号重新定位"，不预先猜行号。

## 现状

以下事实已在当前仓库（基线 `757fd12`）核实，二期实施时须重新核实：

- `GatewayAdapter` 契约只有三方法（`connectors/gateway/registry.py:24`），登记表 `_ADAPTERS`（≈L32）。
- `validate_create_credentials` 对未登记 `custom_fields` kind 抛 `ValueError(...)`（`connectors/builder.py:422`），分支入口 L396。
- 连接器目录主表 `_CATALOG`（`catalog.py:96`）经 `w0-04` 改造后由 `catalog_intranet.compose_catalog(_BASE)` 组装，新增条目走 `catalog_intranet.py::_fork_entries()`，不改 `catalog.py` 本体。
- SSRF 守卫全部放行点（`ssrf_guard.py` 的 `_parse_https_host`≈L20、`validate_https_url`≈L71、`_resolve_validated_ip`≈L87、`safe_request`≈L165）机制归属 `w0-05`，本 spec 不改此文件。
- `TokenQuotaMiddleware`（`agents/middleware/token_quota.py:26`）现状只有 `before_agent`/`abefore_agent`（L39/L43）；挂载点在 `manager.py:2813`。
- `resolve_usage_window`（`db/repos/usage.py:73`）不支持 `week`/当期 `month` 别名。
- `ErrorCode.TOKEN_QUOTA_EXCEEDED`（`errors.py:109`，`_DEFAULT_STATUS`≈L211 → 403）已存在，可直接复用。
- 银行专家发现机制 `default_library_root()`（`experts/catalog.py:758`）与回退集合 `_FALLBACK_BUNDLED_AVATAR_IDS`（L41）已存在。
- `w0-04` 提供的隔离点：`api/intranet_mounts.py::_FORK_DISABLED_MOUNTS`、`catalog_intranet.py::_fork_entries()`。
- `w0-01` 提供的隔离点：`fork_migrate.py::run_fork_migrations()`、独立水位表 `_fork_schema_version`、`forkNNN_<描述>.sql`/`.pg.sql` 命名。

## 方案

按需求拆成五个基本独立的垂直切片，共用两条纪律：新表结构一律走 `forkNNN_` fork 迁移（不用源材料写的 `016_`）；新增文案一律写进 `w0-04` 建立的 intranet overlay，不改上游 `en.json`/`zh.json` 本体。

## 数据模型

新增 fork 迁移（占位名，合入前定号）：`forkNNN_usage_quotas.sql` + `.pg.sql`。

```
CREATE TABLE IF NOT EXISTS usage_quotas (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,        -- PG: GENERATED BY DEFAULT AS IDENTITY
  quota_id      TEXT NOT NULL UNIQUE,
  user_id       INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  scope         TEXT NOT NULL,                             -- user | agent | model
  agent_id      TEXT NULL REFERENCES agents(agent_id) ON DELETE CASCADE,
  model         TEXT NOT NULL DEFAULT '',
  period        TEXT NOT NULL,                              -- lifetime | day | week | month
  limit_tokens  INTEGER NOT NULL,
  enabled       INTEGER NOT NULL DEFAULT 1,
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL,
  UNIQUE (user_id, scope, agent_id, model, period)
);
CREATE INDEX IF NOT EXISTS idx_usage_quotas_user ON usage_quotas(user_id, enabled);
CREATE INDEX IF NOT EXISTS idx_usage_log_user_model ON usage_log(user_id, model, ts);
```

遵守 `{entity}_id` 约定（`id` 整数 PK + `quota_id` 字符串公开 id）。`idx_usage_log_user_model` 是对既有 `usage_log` 的追加索引，随本迁移一起下发。无存量回填需求；未配置任何行的用户由 `infra/users/quota.py` 的 legacy 桥接读 `user_policies` 兜底。

## 配置

无新增 `config.json` 键。供应商 CA/代理存在既有 `providers.extra_json`（经 `w3-05` 加密落库）；配额周期用既有 `default_timezone`；行内网段沿用 `w0-05` 已定义的配置键，本 spec 不重复定义。

## 错误处理

不新增 `ErrorCode`。配额超限复用既有 `ErrorCode.TOKEN_QUOTA_EXCEEDED`（`_DEFAULT_STATUS` 已登记为 403），用 `details` 区分维度。连接器/通道的其他失败路径复用模块已有错误语义。

## 安全考虑

- `extra_json` 回传须经 `w1-01` 脱敏契约（敏感键掩码），落库经 `w3-05` 的 `CryptoProvider`，本 spec 不自建第二套加密。
- 三个连接器的出网请求须经 `w0-05` 的 SSRF 白名单（默认空白名单行为不变）；本 spec 只在部署配置加入行方域名/网段，不改守卫代码。
- 配额是权限型逻辑，`before_agent`/`wrap_model_call` 须在模型调用前完成拦截；`record_turn_usage` 现状把写入异常整段吞掉（`contextlib.suppress(Exception)`），若行方要求"零静默丢账"需另立项（记入待确认项）。
- 行内 IM 入站回调（若需要）复用 `internal_mcp.py` 的 token-in-query 模板，不放宽 `setup_lockdown.py`（只在零用户时生效）。

## 风险与回滚

- 最高：D13 若不成立，行内 IM 实现路径变化；已给出 MQTT 桥接降级路径，应尽早确认。
- 高：供应商 TLS/代理依赖第三方包 `orcakit-harness-agent` 的字段扩展，需内部 fork 或厂商配合；拿不到则降级为沿用 `w2-04` 的进程级 `SSL_CERT_FILE`。
- 中：`record_turn_usage` 会静默吞掉用量写入异常，可能导致配额被无声绕过；本 spec 不改该路径，只记录风险。
- 回滚：五个切片相互独立，均可单独 `git revert`；`forkNNN_usage_quotas` 合入后不可改，回滚需新开一个 fork 迁移做逆向 DDL。
