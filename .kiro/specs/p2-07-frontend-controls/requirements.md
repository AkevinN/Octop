# 需求文档：前端管控

> spec：`p2-07-frontend-controls` ｜ 波次：二期 ｜ 基线：`757fd12` ｜ 预估：19 人日
> 前置：`w1-02-capability-trim`, `w3-02-audit-baseline`, `w3-04-session-and-password` ｜ 全局约束：`.kiro/steering/intranet-transformation.md`

## 引言

Octop dashboard 面向行内网络部署时，需要一套终端管控能力，配合等保测评现场检查：已登录页面叠加身份+时间戳水印、无操作超时自动登出、复制与下载可按策略收敛、高危操作要求二次确认甚至重新输入口令。本 spec 是源分析 `S22-frontend-controls.json` 扣除已归属其他 spec 的部分后的剩余范围：

- 下载出口的后端强制校验与审计留痕（`assert_download_allowed`、`file_download` 能力位、10 个出口挂点、`ui.download*` 审计动作）已由 `w3-02-audit-baseline` 交付；本 spec 只在其上**追加按角色的放行策略**，不重建它。
- 会话表、令牌吊销、`sign_token` 的 `sid` 化、空闲超时的服务端权威判定（`session_idle_timeout_seconds`）已由 `w3-04-session-and-password` 交付；本 spec 的空闲登出只做**客户端活动侦测与触发登出调用**。
- 强制能力开关框架（`capabilities.<name>.enabled`）已由 `w1-02-capability-trim` 交付；本 spec 新配置项复用其登记方式。
- w1-02 已删除的页面与入口不在本 spec 范围内。

**范围内：** 页面水印（内容、防摘除、打印态、全屏与离线降级）；空闲自动登出的前端触发与倒计时提示；复制与下载的前端出口收敛（明确写清"能做到"与"绕不过去"的边界）；高危操作的二次确认（打字校验资源名）与口令/打字降级重认证（`POST /api/auth/reauth`）。

**范围外（归属见括号）：** 下载出口后端强制校验与审计字段（`w3-02`）；会话吊销与服务端空闲超时判定（`w3-04`）；能力开关框架本体（`w1-02`）；验证码终态（`w3-01`）；国密/KMS（`p2-02`）；知识库三级 ACL（`p2-05`）。

## 需求

### 需求 1：页面水印覆盖与内容

**用户故事：** 作为安全合规负责人，我希望已登录页面统一叠加含用户身份与时间戳的水印，以便违规截屏、拍照外发时可追溯到具体人员。

#### 验收标准

1. 当已登录用户打开任意页面（含 antd Modal/Drawer、message/notification 等 body 级 portal）时，水印组件应当以 `document.body` 下唯一固定层的形式渲染，且不依赖具体页面的 React 子树位置。
2. 水印内容应当始终包含当前用户 `username`、`employee_id`（缺失时降级为 user id）与按服务器时区格式化的 `yyyy-MM-dd HH:mm` 时间戳，时间戳格式化应当复用 `dashboard/src/utils/formatMessageTime.ts` 的既有函数，不得使用裸 `toLocaleString()`。
3. 如果 `AuthGuard` 处于"后端不可达仍放行"的降级分支（`user === null`），那么水印应当仍然渲染（降级为"未知用户 + 时间戳"）且不得抛异常。
4. 在 `@media print` 打印场景下，水印应当同样渲染在输出内容上，不得被打印样式吞掉。

### 需求 2：水印防摘除

**用户故事：** 作为安全合规负责人，我希望水印层被脚本或 DevTools 手动移除后能自动恢复，以便提高绕过成本。

#### 验收标准

1. 当水印节点被从 DOM 移除时，系统应当在一帧内检测到并重新插入。
2. 当水印节点的 `display` 被设为 `none` 时，系统应当在 1 秒内检测到并恢复可见。

### 需求 3：空闲自动登出

**用户故事：** 作为安全合规负责人，我希望用户长时间无操作后自动登出，以便降低他人接触已登录会话的风险。

#### 验收标准

1. 在无 `pointerdown`/`keydown`/`touchstart`/`visibilitychange` 等活动事件持续达到策略配置的空闲阈值期间，前端应当调用登出接口、清理本地凭据（含 `octop:active-agent`）并跳转登录页。
2. 当任一标签页发生活动事件时，系统应当通过 `localStorage` 广播机制让其余标签页同步重置计时，避免误登出正在使用中的标签页。
3. 如果空闲登出触发的登出调用命中 `w3-04` 提供的服务端会话吊销，那么用登出前的旧令牌访问受保护接口应当返回 401；本 spec 只负责触发该调用，服务端吊销结果的正确性由 `w3-04` 的验收覆盖。

### 需求 4：复制管控

**用户故事：** 作为安全合规负责人，我希望能按策略关闭复制入口，并清楚知道哪些复制路径管得住、哪些管不住。

#### 验收标准

1. 当复制策略被禁用时，前端唯一的写剪贴板出口应当直接返回未复制且不触碰 `navigator.clipboard`/`execCommand`。
2. 在复制策略禁用状态下，终端（xterm）、Monaco 编辑器、文本选区三类特殊路径应当分别被专门处理（终端收敛既有的 Ctrl+Shift+C 放行分支、Monaco 侧屏蔽右键菜单与剪贴板 action、选区侧对 `copy`/`cut` 事件调用 `preventDefault`）。
3. 设计文档应当明确记录复制管控无法覆盖的路径（F12 读 DOM、直接调用 API、OCR 截屏），不得对外宣称复制已完全闭环。

### 需求 5：下载管控（前端出口收敛与边界）

**用户故事：** 作为安全合规负责人，我希望前端下载入口收敛到一处便于统一管控，并清楚哪些内容仍可通过合法权限取走。

#### 验收标准

1. 前端所有触发文件保存的调用应当收敛到唯一的下载工具函数，不再各自写 `a.download`。
2. 当下载策略禁用时，前端下载按钮应当置灰并给出提示；实际是否放行以 `w3-02` 提供的 `assert_download_allowed` 按角色策略判定结果为准，本 spec 只负责在该函数上追加角色白名单读取，不重复实现后端强制校验。
3. 设计文档应当明确记录已知的、按设计不拦截的预览/只读出口（如 `Content-Disposition: inline` 的媒体预览、知识库文档原文 JSON 接口），并说明这些出口仍可用 `curl -o` 取走内容。

### 需求 6：高危操作二次确认与重认证

**用户故事：** 作为安全合规负责人，我希望删除专家、删除用户、恢复备份等高危操作在执行前要求输入资源名确认、必要时重新验证口令，以便降低误操作与会话劫持的影响面。

#### 验收标准

1. 当高危操作要求"输入资源名确认"时，确认按钮应当在输入内容与目标资源名不一致前保持禁用，且该状态应当能随输入动态更新（不得使用返回 `void`、丢弃 modal 实例的旧版确认弹窗实现）。
2. 当高危操作要求重认证时，前端应当先校验口令、成功后才发起业务请求，业务请求应当携带服务端签发的短时重认证令牌。
3. 如果重认证口令错误，那么 `POST /api/auth/reauth` 应当返回 401 且不得累加登录失败计数；如果携带的重认证令牌缺失、过期或被当作普通访问令牌使用，那么受保护端点应当分别返回明确的拒绝错误码。
4. 如果当前用户是 SSO-only 账号（无本地口令），那么重认证应当降级为"仅要求打字确认"，不得对该类用户返回 500 或无声放行。
